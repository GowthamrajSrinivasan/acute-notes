# Acute-Notes — Phase 5 (AI/MCP) Implementation Plan & Tracker

**Purpose:** track *state* across sessions while implementing Phase 5 / 5b / 5c of the PRD. It is not a second copy of the requirements — the PRD (`acute-notes-prd-claude-code-ai.md`) is the source of truth for what each feature must do. When this file and the PRD disagree, the PRD wins; fix this file.

**How to use this file:** before starting work, read §0–§1 below. Pick the next `Not started` feature in order. After finishing a feature (or a deliberately-scoped slice of a large one), tick its checklist items, flip its Status, run the verification gate, and note any deviation from the PRD under that feature's `Notes:` line before moving on.

**Standing constraint:** no git commits, pushes, or PRs are made from this work — changes stay uncommitted until explicitly asked for.

## 0. Repository state (baseline: 2026-09-25)

The editor MVP is already implemented under `src/`: canvas (`components/canvas/`), rich blocks (`components/blocks/`), pages, persistence (IndexedDB repositories), Yjs sync, history, portability/export, and search all exist. `src/ai/` and `src/mcp/` do not exist yet. This plan starts from a clean slate for AI/MCP and assumes the editor primitives below are stable and reusable as-is:

- Domain commands or their equivalents for object creation/update (used by F30, F21).
- `CanvasRepository` / `PageRepository` / `AssetRepository` style repositories (F27 adds `AISettingsRepository`/`AIUsageRepository` alongside these, not inside them).
- The undo/history system (F19 builds AI transactions on top of it, does not replace it).

If any of these don't hold when a feature starts, stop and reconcile with the PRD/actual code before proceeding — don't paper over a mismatch.

## 1. Standing invariants — re-check on every feature

Condensed from PRD §21; these are the rules most likely to slip across a long, multi-session build.

- [ ] No provider/vendor name, SDK import, or `if (provider === ...)` branch outside `src/ai/providers/` and `src/ai/host/`.
- [ ] Feature/UI code calls only `AIRuntime.run(task, input)` — never an adapter directly, never a vendor SDK.
- [ ] Every structured model result is schema-validated (F29) before it reaches the renderer or a domain command; one repair retry, then a typed failure — never pass unvalidated data through.
- [ ] AI never runs on the canvas rendering/input critical path; every AI call is async and cancellable (`AbortSignal`), and cancellation leaves no partial state.
- [ ] AI mutations are additive and reviewable (F19) — never a silent create/modify/delete outside a reviewed, acceptable, undoable transaction.
- [ ] AI-created objects use the same domain commands as manual creation; no behavior branches on `createdBy`.
- [ ] Secrets (BYOK keys, GitHub/OAuth tokens) never enter documents, Yjs state, exports, sync payloads, MCP resources, logs, or telemetry.
- [ ] No Acute-Notes-owned LLM key anywhere; `@github/copilot-sdk` is the only provider SDK added to the dependency tree.
- [ ] Reconciliation (F37–F39) matches by stable identity, never overwrites a user-edited block without an explicit Apply, and re-analyzes only changed source spans (not the whole document).
- [ ] `npm run typecheck && npm run lint && npm run test` all pass before a feature is marked Done.

### F32 — Optional Decision Model (feature flag)
**Status:** Not started
- [ ] Decision-model role registered as an ordinary `AIProvider`; routes only `preferDecisionModel` tasks
- [ ] Automatic, silent fallback to primary on absence/error/timeout/low confidence

**Good to have, not required — where and how a decision model (e.g. Jev) fits**

This is a cost/latency/token optimization, not a quality upgrade. Without it, the primary provider does the exact same classification-shaped work itself inside the same call — more tokens, more latency, not lower quality. If anything, the routing policy protects quality in the other direction: it falls back silently to the primary whenever the decision model is absent, errors, times out, or returns low confidence (§13.15.9) — a bad decision-model call never gets to override the primary, it just gets discarded.

Where it helps — only classification/routing-shaped calls, never authoring:
- Confidence gate in F28/F31: "does this content need deep AI analysis, or is the local tier enough?"
- `select_template` in F31: which of the 8 `VisualPlan` templates fits, once the AI tier is actually needed
- `assess_change_significance` in F38 (proposed, not yet in the PRD): per changed source section, "substantive change worth a real re-analysis, or cosmetic?" — the main token-savings lever for reconciliation

Where it does **not** apply, regardless of availability:
- Any actual content generation — `extract_entities`, `extract_relationships`, `summarize`, `generate_note`, `transform_note`, `generate_visual_plan` itself — always the primary provider
- F38's matching (`stableKey`) and clean/conflict classification — pure code, a literal fingerprint-hash comparison, no model call either way
- F20/F21 MCP tools like `render_visual_plan` — the external agent already made its own model call; Acute only validates/renders
- F33 Mermaid conversion — a deterministic parser, not a model call
- F22 search — deterministic local search for MVP; a future embeddings tier would be a different capability (`AICapabilities.embeddings`), not this role

How to add it without creating a second implementation path: it's one more `AIProvider` adapter bound to the `"decision"` role (§13.15.12's "new module + one registry line" pattern). Feature code never branches on whether it's configured — only the per-task routing table (`AI_POLICY`) does. If it needs its own SDK/auth flow, that's contained to its adapter folder, and it still must pass F36's contract tests before it's ever offered in Settings.

Not yet written into the PRD, worth adding when F38 is actually built: `assess_change_significance` as a named `AITask` in §13.15.9's suitable-tasks list and in F38's requirements.
